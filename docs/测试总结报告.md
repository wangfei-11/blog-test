# 个人博客系统（blog）测试总结报告

- 测试人员：王菲
- 测试时间：2025.09 ~ 2025.12
- 项目地址：https://github.com/wangfei-11/blog-test

## 一、项目简介

基于 SpringBoot 3 开发的个人博客系统，支持用户登录、博客增删改查、作者信息查询等功能，采用 JWT Token 完成登录鉴权。前后端不分离（HTML + jQuery），共 8 个接口、5 个页面。本人独立完成整套系统全流程测试（功能 / 接口 / UI 自动化 / 性能）。

## 二、测试范围与环境

| 项 | 内容 |
|---|---|
| 测试范围 | 用户模块 3 接口、博客模块 5 接口；登录页、列表页、详情页、新增页、编辑页 5 个页面 |
| 测试工具 | Postman、Selenium WebDriver（Java + JUnit）、JMeter、MySQL、Chrome |
| 测试环境 | Windows 11，JDK 17，SpringBoot 3.2.9，MySQL testdb，端口 8081 |

### 3.4 性能测试（JMeter）

使用 JMeter 对 3 个核心接口开展 100 并发压测（循环 2 次，共 500 请求）：

| 接口 | 样本数 | 平均响应时间 | TPS | 错误率 |
|---|---|---|---|---|
| 登录 POST /user/login | 100 | 3ms | 99/s | 0% |

## 四、缺陷分析

共发现缺陷 **10 个**（功能测试阶段 8 个，接口测试阶段 2 个），全部修复并回归通过：

| 缺陷ID | 缺陷描述 | 严重程度 | 优先级 | 状态 |
|---|---|---|---|---|
| BUG-001 | 登录页不支持回车键提交 | 轻微 | P2 | 已修复 |
| BUG-002 | 参数类型错误返回技术化异常信息，提示不友好 | 轻微 | P2 | 已修复 |
| BUG-003 | 标题未转义，含 script 标签导致存储型 XSS | 严重 | P0 | 已修复 |
| BUG-004 | 更新博客时标题/内容可清空保存 | 一般 | P1 | 已修复 |
| BUG-005 | 编辑页 blogId 缺失或非数字时无提示，编辑器空白 | 一般 | P2 | 已修复 |
| BUG-006 | blogId 不存在或已删除时编辑器初始化成空白，像新增页 | 一般 | P3 | 已修复 |
| BUG-007 | 越权修改他人博客（后端未校验归属） | 严重 | P0 | 已修复 |
| BUG-008 | 详情页内容 img onerror 注入导致存储型 XSS | 严重 | P0 | 已修复 |
| BUG-009 | 新增博客时 title/content 传空串可保存 | 一般 | P1 | 已修复 |

缺陷分布分析：
- **严重缺陷 3 个（30%）**：其中 2 个为存储型 XSS（BUG-003、BUG-008）、1 个为越权修改（BUG-007），均属于安全类问题，通过前端转义 + 后端归属校验双重修复。
- **功能类缺陷 6 个**：集中在参数校验不完善（BUG-004、BUG-009、BUG-010）和异常分支提示缺失（BUG-005、BUG-006）。
- **体验类缺陷 1 个**（BUG-001）：交互细节。

## 五、遗留问题与建议

1. **列表接口返回全量 content 字段**：/blog/getList 返回每篇博客的完整正文，压测时吞吐数据量大（约 13MB/s），且列表页实际只用摘要。建议列表接口只返回摘要字段并加分页，可显著降低传输量与数据库压力。
2. **参数缺失提示未友好化**：getUserInfo / getAuthorInfo 等接口参数缺失时返回系统默认校验文案（含方法名），建议统一为友好提示。

## 六、测试结论

本项目四阶段测试全部完成：功能用例 82 条、接口用例 81 条、UI 自动化脚本 25 条、性能测试 3 接口，共计 **188 条用例**，通过率 100%。发现并推动修复缺陷 10 个（含 3 个严重安全缺陷），全部回归通过；遗留 2 条优化建议。**系统功能、接口、UI、性能均满足上线标准。**

## 七、个人总结

- 本次测试完整走完「用例设计 → 手工执行 → 接口测试 → UI 自动化 → 性能测试 → 报告」全流程。相比 chatroom 项目，本次缺陷设计覆盖了 XSS、越权等安全测试点，测试点设计能力进一步提升。
- 测试中发现的问题以「测试 + 开发」双角色闭环处理，缺陷从发现到修复回归的周期更短，加深了对缺陷根因（前端校验可绕过、后端必须兜底）的理解。
- UI 自动化踩坑记录：列表页标题为 div 元素，需按 .blog 容器定位；editormd 内容在 CodeMirror 组件中，回显断言需读组件 DOM 并显式等待；错密码用例数据需满足长度校验才能走到业务校验分支。
- 性能测试踩坑记录：JMeter 聚合报告"文件名"框误填脚本路径会污染 .jmx 文件（结果留档应使用 .jtl）；业务失败返回 HTTP 200，需加响应断言校验业务 code。
